重复文件清理器  v2.6  ·  图形界面
======================================================================

【快速开始】

  双击 run_gui.bat 打开界面（或用打包好的 Dedup.exe，免安装）。

  也可以：
    把要检查的文件夹直接拖到 run_gui.bat 上松开
    或在命令行运行  python dedup_gui.py "D:\照片"

  第一次打开建议先选一个小文件夹试一遍，熟悉流程后再处理大目录。


【界面结构】

  左侧导航分两组：

  工作区
    扫描文件夹   选择目录、设置检测内容和扫描选项
    扫描结果     分组浏览结果，勾选并清理重复文件
    运行日志     每一步做了什么、跳过了什么，都在这里

  工具箱
    文件整理     按类型或日期把文件归到子文件夹，可撤销
    批量重命名   查找替换、前后缀、序号模板，可撤销

  左下角状态卡显示当前状态；左下角 v2.6 表示本地离线版本。
  侧栏底部「白天主题 / 深色主题」按钮可随时切换配色，默认深色，
  选择会记住，标题栏也会跟着变浅或变深；切换不会打断正在进行的扫描。


【第一步：扫描】

  1. 点「选择文件夹」，或直接把路径粘贴进输入框，回车即可开始。
  2. 勾选要查找的重复类型（可多选）：

      完全重复   字节完全一致的文件，零误判（推荐）
      相似照片   同一张图的不同压缩、格式、旋转、镜像版本（最常用）
      重复视频   帧序列接近的视频，需要解码，速度较慢
      重复音乐   同一首歌的不同码率版本
      同名相似   去掉「副本 / Copy (2)」标记后文件名相同，
                 适合找回同一份文档的不同修改版本
      重复目录   目录内直接文件的文件名 + 大小完全一致，内容未校验，
                 默认不勾选，不能直接清理；单个文件的目录也可成组

  3. 右侧扫描选项：

      识别严格程度  宽松 / 标准（推荐）/ 严格
                    宽松漏检少但可能误判，严格更保守
      最小文件大小  不限 / 1 MB / 10 MB / 100 MB
                    大目录建议设 1 MB，跳过缩略图和缓存
      排除目录      额外跳过的子目录，用逗号分隔，例如：缓存, 备份
      包含子文件夹  关闭后只扫描当前目录
      指纹缓存      开启后，重复扫描同一批文件会复用上次结果，快很多
      保留策略      决定每组默认留住哪一个（结果页也能随时改）

  4. 点「开始扫描」，进入进度环页面，可随时取消。

  扫描全程只读取文件，不会修改、移动或删除任何内容。
  指纹缓存只记录文件哈希，文件大小或修改时间变了会自动重算。


【第二步：查看结果】

  每个「组」代表内容相同或高度相似的一批文件。

  卡片顶部：类型标签、组内版本数、可释放空间、重置 / 对比 / 打开位置。
  卡片中间：缩略图。照片显示图片本身，视频截取画面，其他文件显示类型。

  每组默认保留一个推荐项，标记为绿色「保留」，其余版本默认勾选（准备清理）。

  排序与选择：

    「排序」        可释放空间 / 相似度 / 文件数 / 文件名
    「保留策略」    智能推荐（清晰度·体积·时间）/ 最旧 / 最新 / 最大 /
                    路径最短 / 扫描目录顶层
    「快捷选择」    全选除保留项 / 只选相似度 ≥ 90% / 只选完全重复 / 取消选择

  单个文件的操作：

    单击缩略图        勾选 / 取消勾选这个文件
    双击缩略图        用系统默认程序打开该文件
    右键缩略图        设为保留项 / 对比 / 取消本组选择 / 定位 / 复制路径
    点「保留」标记     直接把这一项设为保留
    「重置」          本组恢复为默认的保留与勾选
    「对比」          并排查看组内两个文件（见下）

  对比窗口：

    左右两栏各显示一个版本，滚轮缩放、拖动平移，两边同步。
    底部按钮：适应窗口 / 100% / 打开 / 定位；
    勾选「差异热图」会把左边图像与右边图像的像素差用红色高亮出来，
    重压缩、轻微裁切一眼可见。左右方向键切换右边的版本，Esc 关闭。

  每组至少会保留一个文件，界面不会允许你把一组全部勾选；
  标着「保留」的那一项本身也点不了勾选，想删它得先把别的文件设为保留。
  保护文件夹内的文件会显示为受保护，无法被勾选或清理。

  顶部还有：
    分类筛选    全部 / 完全重复 / 相似照片 / 重复视频 / 重复音乐 / 同名相似
    搜索框      按文件名过滤，输入即搜
    导出报告    把当前结果导出为 CSV（Excel 可直接打开）


【第三步：清理】

  1. 确认底部统计：「已选 N 个文件 · 可释放 X」。
  2. 点「移入回收站」，确认后执行。
  3. 清理完成后结果自动刷新，清空的组会消失。
  4. 回收站里的文件随时可以还原，误删也不用慌。

  需要彻底删除时，在确认框里选「永久删除…」，会再确认一次。
  永久删除不进回收站，无法恢复，请谨慎使用。

  「还原上次清理」会把上一次移入回收站的文件放回原位置。
  还原时会读取回收站里的原始路径，不会覆盖已有同名文件（冲突的会跳过
  并在日志里列出）。永久删除的文件无法还原。

  如果部分文件提示失败，通常是权限不足、文件只读或被别的程序占用，
  关闭占用程序后重新扫描、再清理一次即可。


【工具箱：文件整理】

  按类型或日期把文件归到子文件夹，适合整理下载目录、相机卡、素材盘。

  1. 选择要整理的文件夹。
  2. 选择整理方式：

       按类型   照片/JPG、文档/PDF、音频/MP3…
                可关闭「保留两级目录」，只分到「照片 / 文档」一级
       按日期   年 / 年-月 / 年-月-日 三级可选
                照片可优先使用 EXIF 拍摄日期，没有则用修改日期

  3. 选择执行方式：

       移动 / 复制   复制会保留原位置文件
       包含子文件夹  关闭后只整理当前目录
       删除空文件夹  移动完成后顺手清理变空的旧目录

  4. 点「预览整理」，确认每个文件将去的位置和分类统计。
  5. 点「执行整理」并确认。

  每次整理都会生成操作记录，执行过程中就会持续写入，
  即使中途断电或强制关闭，已经移动的文件也能点「撤销上次整理」放回原位。
  撤销时如果原位已有同名文件，会跳过并写入日志。


【工具箱：批量重命名】

  规则按顺序叠加，扩展名始终自动保留。

    查找替换     把文件名里的文字替换掉，可选忽略大小写
    添加前后缀   例如加 2025_ 前缀、_已整理 后缀
    命名模板     用变量组合文件名：
                   {原名}  原文件主名
                   {n}     序号（可设起始数字与位数 1/2/3）
                   {日期}  修改日期，如 20250807
                 例如「旅行_{n}」→ 旅行_01.jpg、旅行_02.jpg
    英文大小写   保持不变 / 全部大写 / 全部小写 / 首字母大写

  预览在后台线程里生成，大目录也不会卡住界面；改动规则后会以最新一次为准。
  撞名时会自动加 (2)、(3)，并在右侧标注「自动编号」。
  执行采用两阶段改名，A↔B 互换、仅改大小写都能正确完成。
  确认无误后点「执行重命名」，同样可以「撤销上次改名」。


【工具箱：照片去水印】

  用来处理你自己照片上的水印（自己加的、相机/手机自动加的、导出时带的）。
  1. 选照片：可以直接选「照片所在文件夹」，也可以点下面的「选择照片…」
     只挑一两张（可多选、可跨文件夹）。挑完右侧预览第一张并画出红框，
     处理完会自动弹「前后对照」窗口，左原图右结果，滚轮缩放、Esc 关闭；
  2. 选位置预设（右下角 / 左下角 / 底部整条），不合适就手填
     左边距 / 上边距 / 宽度 / 高度（单位是百分比）；
  3. 点「开始处理」。结果默认存到源文件夹下的「_去水印」子目录，
     文件名带「_去水印」后缀，**原图一个字节都不会动**；
     已经处理过的同名输出会自动跳过，重复点不会越生成越多。

  默认（两个开关都不开）：按框形状自动挑补法——横条走竖列复制、竖条走
  横行复制、近方形走四方向反射中位数，四边都做接缝亮度校正（天空、逆光
  渐变不会再出现台阶），没盖到的像素由局部扩散兜底。所以：
    * 水印在边缘、背景有纹理（草地、砖墙、天空、合影）时效果最好，
      接缝基本看不出来；
    * 水印压在主体、人脸或文字上时默认档不可能完全无痕，会糊一块，
      这时改用「纹理合成」或「高质量」；
    * 底部整条相机构时水印太浓的，也可能留下横向痕迹。
  纯本地、不联网、不用模型，单张几十毫秒；框外像素一个都不动。

  三档怎么选：
    默认自动     —— 快，绝大多数角落 logo / 时间戳 / 水印条够用；
    纹理合成      —— 开「纹理合成（中档）」，草地、布料、砖墙等重复纹理
                     比反射自然，约 0.5~1 秒一处，不用模型；
    高质量 LaMa  —— 开「高质量」，水印压在人物/结构上时最自然，
                     需要 198 MB 模型，约 7 秒一处（载入模型再等约 40 秒，
                     打包版首次点会明显卡一下，这是正常的）。
  两个开关互斥：开了高质量，中档会自动关掉并置灰。
  **模型就绪时「高质量」默认就是开的**：实测半透明水印压在头发/皮肤/衣服上
  时，几何填充（反射、条纹复制）会把一块区域镜像或抹糊，只能算“能看”，
  而 LaMa 能把边缘接回结构；宁可多等几秒，也别娶一张穿帮的图。
  想快就把开关关掉，回到毫秒级的几何填充。

  零散选来的几张照片可以来自不同文件夹：「存到「_去水印」子文件夹」开着就
  在每张照片旁边建一个，关掉就紧挨着原图（仍不会覆盖原图）。

  框的位置会被记住（下一次打开就自动画好，也自动用在「一键抠」上）。

  一张图有多个水印：直接把每个水印各拖一个框（右边预览上拖就行），
  或者手填数值后点「按数值添加」；标签里的「区域：N 个」就是当前框数。

【一键抠浅色水印】

  表格、文档截图这类「白底上平铺一层浅黄/浅色半透明水印」的图，
  不用拖框：页面上直接点「一键抠浅色水印」。
  它现在还会顺带套用你框过的区域：拖一次框（比如“AI生成”这种白字徽标）
  程序会记住位置，下次点「一键抠」自动用同一位置补掉，不用再框。白字是
  不透明的，反解救不回来，只能靠补，所以一定得有一个位置。
  照片（不是文档）不会再做反解：实测人像上“淡色水印”掩膜会吃掉 7% 的
  像素（皮肤、汗光、亮草地），整张发灰；色度高的图现在直接跳过反解，
  只走「框选 + 高质量」。

  * 原理：水印是半透明叠加（像素 = (1-α)·背景 + α·黄色），程序估出 α
    后反解出背景，而不是去“补图”——文字和表格线的像素根本没被碰过，
    不会留下补图常见的暗边；纸面上残留的淡色和亮度差，会在“平坦且附近没有
    文字”的地方用周围像素重新铺平，所以浅灰渐变背景上也不会留影子；
  * 速度：约 240 万像素（1152×2048）的截图约 3 秒一张；不联网、不需要模型；
  * 适用：白底/浅灰底的淡色半透明水印——淡黄、淡蓝、淡粉、淡绿都会
    自动认出来（先判断图上主色调是哪一种，再按同一种颜色反解）；
    完全没偏色的淡灰水印也支持：靠“同行同列连续段短”把笔画和长直线
    （表格线）区分开，只抹笔画；
  * 阈值不写死：按图片自身的噪声（中位数绝对偏差）自动定，清白的
    截图能抓到 3 个色阶的淡差，噪点多的图会自动抬高门槛；
  * 参考色不写死：会先从掩膜里自估水印颜色，再按「反解后残余偏色最小」
    在固定色表 / 自估值 / 两者折中之间挑一个，各家 App 的非标准水印色
    也不容易把覆盖率估偏（残影或过矫正）；
  * 不适用：不透明贴纸、彩色 logo、压在深色照片上的水印——
    这些请用上面的拖框 + 高质量（LaMa）模式；
  * 跑完会自动弹出「前后对照」窗口（左原图 / 右结果，滚轮缩放、拖动平移、
    Esc 关闭），不用自己去文件夹里翻；
  * 输出规则与拖框模式相同：另存到「_去水印」子目录，不会覆盖原图。

【纹理合成（中档）：无需模型】

  打开「纹理合成（中档）」后，程序会从框外一圈圈往里找最像的图块来补，
  整块一起复制而不是逐像素取中位数，草地、布料、砖墙这类重复纹理的
  颗粒走向能接上，不会平均成糊块。纯 numpy，不下载任何东西。
  * 速度：约 0.5~1 秒一处，比默认档慢、比高质量快一个数量级；
  * 适合背景有重复纹理的水印；纯色/渐变背景用默认档反而更干净；
  * 框外像素同样一个都不动。

【高质量模式：LaMa 模型】

  水印压在人物、衣服、栏杆这类有结构的地方时，反射补会露馅。
  打开「高质量（LaMa 模型）」后用神经网络按语义补，接缝和结构能续上。
  * ≤512 的窗口直接贴进 512 画布（反射补边），推理完按原像素取回，
    不放大也不缩回，框内细节更锐；大框改走带重叠的滑窗平均，
    不会把整块缩小成 512 而糊掉；
  * 需要：程序目录下的 models\lama_fp32.onnx（198 MB，Apache-2.0）；
    没有这个文件时开关是灰的，其它功能不受影响；
  * 速度：每次推理约 7 秒（8 核 CPU 实测），有 3 处水印就是 20 秒左右；
    首次使用要先把模型加载进内存，约 50 秒，之后一直很快；
  * 首次点开这一页时程序会自动在后台加载模型，不用你等；
  * 全程离线，不上传不联网。

【日志与设置】

  数据目录：%APPDATA%\Dedup（存档设置、缓存、扫描历史）
  便携模式：程序目录下放一个 portable.ini，数据改存到程序目录的“用户数据”
            文件夹，整个文件夹拷到别的电脑/U 盘设置也跟着走；删掉就干净
    dedup_settings.json   记住上次目录、严格程度、大小过滤、排序、保留策略、主题
    dedup_cache.sqlite3   扫描指纹缓存，可随时删除，删除后下次扫描重新计算
    _操作记录\            整理 / 重命名 / 清理的操作记录，用于撤销；保留最近 12 份
    dedup_error.log       只有启动出错时才会生成，反馈问题时请附上这个文件

  旧版本放在程序目录里的 dedup_settings.json / dedup_cache.json
  会在第一次启动时自动迁移过去。

  日志页最多保留最近 3000 行，可随时点「清空日志」。


【关于判定】

  除了「完全重复 / 相似照片 / 重复视频 / 重复音乐 / 同名相似 / 重复目录」，
  结果里还可能出现两类只作提示、默认不勾选的组：
    * 格式副本：同一张照片的 RAW+JPEG、HEIC+JPG。字节不同、内容同一张，
      默认保留 RAW，避免把底片当副本删掉；
    * 重复压缩包：压缩包内条目名、CRC、解压后大小完全一致（只是压缩级别
      或时间戳不同），解压出来是同一份东西。只认 zip 家族（zip/jar/apk/
      whl/epub 等），7z/rar 需要外部命令，暂不支持。
  另外，文件名像截图的（Screenshot / 屏幕截图 / Snipaste…），相似照片组的
  说明后面会标「（截图）」，方便整组看一眼再决定留哪张。



  完全重复：四级确认，零误判。
            大小分组 → 首尾各 4KB 指纹（≤1MB 直接整读）
            → 大文件（>8MB）中部采样 → 整文件哈希。
            同一个物理文件的硬链接/重复挂载只算一次，不会提示你"删除"它。

  相似照片：8 个方向（4 个旋转 × 2 个镜像）分别取 dHash64 与 pHash256，
            粗筛用「全方向最小汉明距离」（严格等价于枚举 8×8 个方向对），
            → 复核 pHash + 4×4×4 RGB 直方图 → 颜色和长宽比校验
            → 完全链接聚类（A~B、B~C 但 A 不像 C 时不会硬并成一组）。
            同一张图的重新压缩、缩放、旋转、镜像、轻微裁切都能归到一组，
            无关图片不会误判。整图只缩一次、方向在小数组上旋转，
            单张指纹耗时约为旧版的 1/7（同机实测 7.5×）；
            HEIC/HEIF 需要安装 pillow-heif，装了就能读。

  所有级别得出的结论都要先过一道「拍摄信息否决」：两台相机型号不同，
  或同一台相机但拍摄时间差超过 2 秒，就是先后按了两次快门，画面再像也
  不是同一张照片的副本（副本另存、压缩、裁切、堋目录都会原样保留拍摄
  时间，所以不会误伤真副本）。没有拍摄信息的图不做这个判断，行为不变。
  （以前同一场景的连拍会被当成互相重复，这一版修好了。）

  判定分六级，从便宜到贵逐级放行，任一级过门即合并：

    ① 同尺度      dHash 粗差 + pHash 细差 + 结构相关 + 颜色布局
    ② 分块救援    32×32 高频切 4×4 块各算相关，丢掉最差的 3 块再平均。
                  贴纸、大字、局部马赛克只污染个别块，整幅点积却会被拉
                  到门限以下；再叠加稳健布局（丢最差 1/4 块）与连拍否决。
    ③ EXIF 救援   同机型 + 拍摄时间 ≤2 秒。这条路误报风险最高（连拍相邻
                  帧人动一下也满足），所以读 SubSecTime 区分连拍帧，并且
                  要求「体积或像素面积明显更小」这类派生副本特征才放行。
    ④ 缩放/旋转   中心梯子 → 内缩窗口（去白边）→ 偏心矩形窗口 →
                  小角度旋转（±3/5/10°）。候选队列按「径向缩放不变签名 +
                  深度余弦」排序，不再靠直方图距离猜，队列上限不会静默
                  漏掉真候选。
    ⑤ 任意角度    Fourier–Mellin 对幅度谱做 log-polar 相位相关，一次解出
                  旋转角与缩放比，覆盖 7°/15° 这类离散梯子够不着的角度；
                  平移用普通相位相关直接估。只产出候选，是否合并仍由对齐
                  后的 NCC + 布局双门决定。
    ⑥ 深度特征    可选层，见下。

  深度特征（可选，不联网）：models 目录里放一个 705 KiB 的
            photo_embed.onnx，每张图多算一个 128 维向量，余弦相似度作为
            独立判据——高余弦时与手工门联合提召回（重调色 + 大幅裁切 +
            贴纸叠加这类手工特征全崩的情况），低余弦时否决 EXIF/分块救援
            压误报。没装 onnxruntime 或没放模型就整层跳过，功能不受影响，
            也不会去下载任何东西。

  缩略图缓存是 96×96（早期 64×64），深裁切后仍有足够像素做 NCC。
  实测（86 张合成照片 / 281 对真副本 / 3374 对假对）：
            手工链路召回 36.7%，全链路 81.1%，误报 0；
            贴纸、重调色、强压缩、7°/15° 旋转、40% 裁切、加白边
            七类单重退化全部 10/10。

  实测速度（283 个文件 / 180 MB，其中 200 张照片，8 线程）：
            冷扫描 2.3 秒左右（旧版同条件 5.6 秒），
            指纹缓存生效后 0.2~0.4 秒。照片指纹是主要开销，
            纯大文件的完全重复检测约 200~500 MB/秒。

  重复视频：时长相差 20% 内才比对，按时长均匀抽 15 帧做 dHash，
            按匹配帧占比判定。优先用 ffmpeg 抽帧（本机已装），
            没有 ffmpeg 时退回 OpenCV；两者都没有则跳过视频检测。

  重复音乐：优先读标签（艺术家/标题/专辑）归组；装了 chromaprint 的
            fpcalc 时再比对音频指纹，避免把同名不同曲误判。
            没装 fpcalc 时只按标签归组，日志里会写明「未启用音频指纹」。

  同名相似：去掉「副本、拷贝、Copy、Copy (2)」等复制痕迹后，
            主文件名相同即归为一组；一组超过 24 个文件时忽略该组，
            避免「新建文档」这类通用名称刷屏。这类组默认不勾选，
            因为文件名相同不代表内容重复。

  严格程度对应的阈值（照片：粗筛 dHash / 复核 pHash / 直方图距离；
  视频：单帧粗差 / 精差 / 匹配帧占比）：

    宽松  照片 12 / 62 / 0.38    视频 14 / 120 / 0.50
    标准  照片  8 / 42 / 0.26    视频 10 /  96 / 0.60
    严格  照片  5 / 26 / 0.16    视频  7 /  72 / 0.75

  默认跳过 $RECYCLE.BIN、System Volume Information、node_modules、
  .git、.vs、AppData、Windows、Program Files 等目录。


【旧版命令行启动器（仍然可用）】

  run.bat           只查重。重复内容集中到结果目录，原文件不动（硬链接）。
  run_organize.bat  查重 + 按类型归档。会把文件移动整理，执行前会询问。
  run_move.bat      查重 + 重复文件直接移入结果目录，不归档。

  这三个 bat 调用的是 dedup_finder.py，与图形界面共用 dedup_core，
  但命令行默认不做音频和同名组检测。适合批处理或在没有图形界面的环境使用。

  移动文件前会先询问确认（加 --yes 跳过询问）。移动操作会写一份撤销
  记录，可用 python dedup_tools.py undo --kind finder 还原。


【依赖】

  Python 3.10 以上，需要 numpy、Pillow。
  可选：ffmpeg（视频抽帧，推荐）、opencv-python（没有 ffmpeg 时兜底）、
        pillow-heif（HEIC 照片）、fpcalc（音频指纹）。
  缺少可选组件时对应类型会跳过并写进日志，其余功能不受影响。
  整个工具本地离线运行，不上传任何文件。


【打包】

  python -m PyInstaller dedup_gui.spec --noconfirm
  产物：dist\Dedup.exe（单文件、无控制台，双击即用）。


【注意】

  1. 视频解码较慢，上百个视频请耐心等待；可先用「严格」+ 最小 10MB 试。
  2. 扫描不会生成任何输出目录，结果只存在内存里；需要留档就导出 CSV。
  3. 清理动作只在点击「移入回收站 / 永久删除」并确认后发生。
  4. 整理 / 重命名会直接改动磁盘；先预览、再执行，误操作可撤销。
  5. 第一次清理或整理前，建议先在小目录上完整走一遍流程。
